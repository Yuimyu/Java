# HelloWorld.java 解説（C言語との比較・初心者向け）

対象コード:

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

C言語の`printf`はわかるけど`struct`やポインタはうろ覚え、という前提で、必要な予備知識から順番に積み上げて説明します。

---

## 事前知識1: C言語の `struct` って何だったか

`struct`（構造体）は、**複数のデータをひとまとめにした「型」**です。

```c
struct Dog {
    char name[20];   // 名前
    int age;         // 年齢
};
```

これは「Dogという構造体には、nameとageという2つのデータが入っている」という**設計図**を作っただけです。まだ実際の犬は1匹もいません。

実際にデータを使うには、その設計図から**実体**を作る必要があります。

```c
struct Dog myDog;      // 実体を1つ作る
myDog.age = 3;         // 実体の中のageに値を入れる
```

ここで覚えておいてほしいのは、**「設計図（struct Dog）」と「実際に使う実体（myDog）」は別物**という点です。これが後で出てくるJavaの`class`と`static`の理解に直結します。

---

## 事前知識2: ポインタと `char *argv[]` って何だったか

`char *`は「char型（1文字）が並んでいるメモリの先頭アドレスを指すポインタ」で、C言語では文字列をこの形で扱います。

```c
char *name = "Taro";   // "Taro"という文字の並びの先頭アドレスをnameに入れる
```

`char *argv[]`はこれの配列版で、「文字列（`char *`）がいくつも並んでいる配列」です。C言語の`main`関数でコマンドライン引数を受け取るときに使いましたね。

```c
int main(int argc, char *argv[]) {
    printf("%s\n", argv[0]);   // 実行時に渡された1つ目の文字列を表示
}
```

例えば `./program hello world` と実行すると、`argv[0]`には`"./program"`、`argv[1]`には`"hello"`、`argv[2]`には`"world"`が入ります。「プログラム実行時に外から渡された文字列の一覧」というのが役割です。

---

## 事前知識3: Javaの「クラス」と「オブジェクト」

Javaの`class`は、先ほどの`struct`の考え方をさらに発展させたもので、**データだけでなく、そのデータを操作する処理（関数）も一緒に入れられる設計図**です。

```java
class Dog {
    int age;                       // データ（structのメンバと同じ）

    void bark() {                  // 処理（structにはこれがなかった）
        System.out.println("ワン!");
    }
}
```

そして、Cで`struct Dog myDog;`と書いて実体を作ったのと同じように、Javaでは`new`を使って実体（**インスタンス**、または**オブジェクト**と呼びます）を作ります。

```java
Dog myDog = new Dog();   // 実体(インスタンス)を作る
myDog.age = 3;           // 実体の中のageに値を入れる
myDog.bark();            // 実体を通して処理を呼び出す → "ワン!"と表示される
```

ここでも大事なのは、**`class Dog`という設計図だけの段階では、`bark()`を呼び出すことはできない**という点です。「どの犬が吠えるのか」を決めるために、まず`new`で実体を作る必要があります。

## 事前知識4: `new` は具体的に何をしているのか

先ほど`Dog myDog = new Dog();`という行が出てきましたが、この`new`が何をしているのかを掘り下げます。

事前知識3で説明した通り、`class Dog { ... }`はあくまで「設計図」でした。設計図の段階では、実際に使える犬はまだ1匹も存在していません。`new`は、**この設計図をもとに、実際に使える実体を1つ作り出す**処理です。

```java
Dog myDog = new Dog();
```

この1行が実行されると、順番に次のことが起こります。

1. **実体を1つ作る**：`Dog`という設計図の通りの形をした、新しい実体（**インスタンス**、または**オブジェクト**と呼びます）が1つ生まれる
2. **データの初期化**：その実体の中にあるデータ（`age`など）に、型ごとの初期値が自動で入る（`int`なら`0`、`boolean`なら`false`など）。何も入っていない空っぽの状態にはならず、必ず何らかの決まった初期値から始まります
3. **コンストラクタの実行**：`Dog()`という、クラス名と同じ名前を持つ特別な初期化専用の処理（**コンストラクタ**と呼びます）が自動的に呼ばれ、必要な初期設定を行う
4. **できた実体を渡す**：こうして出来上がった実体を、`myDog`という変数に代入する。これ以降、`myDog`という名前を通してこの実体を操作できるようになる

コンストラクタは例えばこんな感じで書きます。

```java
class Dog {
    int age;

    Dog() {                              // コンストラクタ(クラス名と同じ名前、戻り値なし)
        age = 0;
        System.out.println("犬が生まれました");
    }
}
```

```java
Dog myDog = new Dog();   // 実行すると "犬が生まれました" と表示される
```

つまり`new`は、**「設計図(クラス)から、実際に使える1つの実体(インスタンス)を作り出し、初期設定までしてくれるキーワード」**です。`class`が「型紙」だとすれば、`new`は「その型紙を使って実際に1着服を仕立てる」ような処理だとイメージするとわかりやすいです。

なお、作った実体が不要になったときの後片付け（メモリの解放）はJavaが自動でやってくれるので、プログラマが明示的に「片付け」を書く必要はありません。この点は今は覚えなくても大丈夫です。

## 事前知識5: `static` とは何か

`static`をつけると、**「`new`で実体を作らなくても、設計図（クラス）の名前から直接呼び出せる処理」**になります。

```java
class Dog {
    static void hello() {
        System.out.println("Hello");
    }
}
```

```java
Dog.hello();   // newしていないのに、クラス名.メソッド名 で直接呼べる
```

普通のメソッド（`bark()`など）は「どの実体に対する処理か」が必要なので実体がないと呼べませんが、`static`がついたメソッドは「実体に関係なく、いつでも誰にでも同じ処理」なので、実体なしで呼べるわけです。

## ここまでの知識でHelloWorld.javaを読み解く

### 1行目: `public class HelloWorld {`

```java
public class HelloWorld {
```

Cの`struct`が「データだけの設計図」だったのに対し、Javaの`class`は「データと処理をまとめた設計図」です。`HelloWorld`という名前の設計図（クラス）をこれから作りますよ、という宣言です。

- `public`：Cにはなかった概念です。「このクラスは他のファイルからも自由に使ってよい」という公開範囲の指定です。付けないと、同じ場所からしか使えない扱いになります。
- 重要なルール：ファイル名（`HelloWorld.java`）と、この`public class`の名前（`HelloWorld`）は必ず一致させる必要があります。

### 2行目: `public static void main(String[] args) {`

```java
public static void main(String[] args) {
```

これがCの`int main(int argc, char *argv[])`に相当する、**プログラムの開始地点**です。1つずつ分解します。

| 部分 | 意味 | なぜ必要か |
|---|---|---|
| `public` | 外部から呼び出せる | プログラムを実行するとき、`HelloWorld`クラスの**外側**にいる「JVM（Java実行環境）」が`main`を呼び出しに来ます。`public`がないと「クラスの外からは呼べない」扱いになり、JVMが呼び出せずエラーになります。 |
| `static` | 実体(`new`)がなくても呼べる | プログラムが起動した瞬間、まだプログラム内のどのオブジェクトも作られていません（事前知識3の`myDog`のような実体がまだ存在しない）。実体を作ってから初めて処理を呼べる普通のメソッドでは、そもそも一番最初に呼ぶ処理を用意できません。そこで「実体がなくても呼べる」`static`にすることで、JVMは何もない状態からいきなり`main`を呼び出せます。 |
| `void` | 戻り値なし | Cの`main`は`int`を返して終了コードにしていましたが、Javaで終了コードを指定したい場合は`System.exit(数値);`という別の書き方をするため、`main`自体は何も返さない`void`にします。 |
| `main` | メソッドの名前 | JVMは「`public static void main(String[] args)`という決まった形のメソッド」をあらかじめ探すように作られています。名前も形もこの通りに書かないと、JVMに見つけてもらえません。 |
| `(String[] args)` | コマンドライン引数 | Cの`char *argv[]`と同じ役割で、「プログラム実行時に外から渡された文字列の一覧」です。Javaでは1文字ずつのポインタ配列(`char *`)の代わりに、文字列を安全に扱う`String`という専用の型を使い、その配列`String[]`として受け取ります。ヌル終端やメモリ管理を自分で気にする必要がないのがCとの違いです。 |

例えば`java HelloWorld foo bar`と実行すると、Cの`argv[1]`が`"foo"`だったのと同じように、Javaでは`args[0]`が`"foo"`、`args[1]`が`"bar"`になります（Javaの`args`にはCの`argv[0]`にあたる「プログラム名自身」は含まれない点だけ違います）。

### 3行目: `System.out.println("Hello, World!");`

```java
System.out.println("Hello, World!");
```

Cの`printf("Hello, World!\n");`に相当します。ただしJavaには「`printf`のようにどこからでも呼べる独立した関数」という概念がありません。**処理は必ず何らかのクラス・オブジェクトに所属していないといけない**というルールがあるからです（事前知識3を思い出してください。`bark()`が`Dog`というクラスに属していたのと同じです）。そのため、次の3段階をたどって画面に文字を出します。

1. `System`：Java標準ライブラリに最初から用意されている「システム機能をまとめたクラス」
2. `System.out`：`System`クラスが`static`で持っている「標準出力（画面）を表すオブジェクト」（Cでいう`stdout`にあたる実体だと考えるとイメージしやすいです）
3. `.println(...)`：その`out`オブジェクトが持つ「1行出力して改行する」処理（メソッド）

`println`は"print line"の略で、Cの`printf`と違い、`\n`を書かなくても自動的に改行してくれます。

### 4〜5行目: `}` `}`

```java
    }
}
```

それぞれ`main`メソッドの終わり、`HelloWorld`クラスの終わりを表す閉じ括弧です。中括弧`{}`で範囲を区切る考え方自体はC言語と同じです。

## まとめ

```
public class HelloWorld {              ← 「HelloWorldという名前の設計図(クラス)を作るよ」
    public static void main(...) {     ← 「外部のJVMが、実体を作らずいきなり呼び出せる開始地点だよ」
        System.out.println(...);       ← 「Systemクラスのoutオブジェクトのprintln処理を使って画面に表示するよ」
    }                                   ← mainの終わり
}                                       ← クラスの終わり
```

C言語との一番の違いをひとことで言うと、**Javaでは「関数やデータを単独でファイルに書く」ことができず、必ず`class`という設計図の中に入れ、必要なら`new`で実体(オブジェクト)を作ってから使う**という点です。`static`は「実体を作らなくても使える特別な処理」を表す目印だと覚えておくと、`main`メソッドの意味が理解しやすくなります。
